## ドラッグ&ドロップのライブラリ(設計書「実装時に比較」)
| 候補 | 評価 |
|---|---|
| **@dnd-kit/core(採用)** | ポインタ・タッチのセンサーを分けられ、`DragOverlay` で「傾き + 影」を自由に描ける。React 19 で動作。キーボード操作は標準のセンサー(座標移動)だと列移動に向かないため、**メニューと `Shift+←/→`** を別に用意した |
| @hello-pangea/dnd | キーボード操作が組み込みで手軽だが、見た目(傾き・影)の自由度が低く、動きは同ライブラリの作法に縛られる |

タッチは「200ms 長押しでドラッグ開始」にして、縦スクロールを妨げないようにした。マウスは 6px 動いたらドラッグ(クリックと区別)。

## 設計書から外れた点・補った点
1. **状態の値は英語コード**(`todo` / `in_progress` / `review` / `done`、版は `draft` / `submitted` / `approved` / `rejected`)。表示名は日本語ラベルで、API は `status_label` も返す。DB・API の値を日本語にすると将来の連携で扱いにくいため。
2. **プロジェクトを作った人は、そのプロジェクトのレビュアーになる**。そうしないと作成者が自分のプロジェクトを編集も承認もできない。他のメンバーの追加は管理画面(`/admin/`)で行う(設計書にメンバー管理の API・画面は無い)。
3. **`is_staff` でも承認はできない**(レビュアーの役割が要る)。設計書 §3.3「承認できるのは、プロジェクトのレビュアーのみ」を字義どおりに実装した。ただし管理者は全プロジェクトを閲覧でき、承認以外の編集はできる。
4. **閲覧者(viewer)は書き込み不可**(ノートも含む)。設計書は閲覧者のノート可否を定めていない。
5. **ヒントとしての `next_statuses`** をタスクの応答に追加。遷移表(サーバー)の結果を返し、UI が遷移ルールを二重に持たないため。権限や「版が必要」などの追加条件は含まない(最終判断は `transition` のみ)。
6. **遷移の検査順**: 遷移表 → 権限(403)→ 追加条件(409 `version_required`)。「未着手 → 完了」は誰が試しても 409。
7. **`shot` は未実装**(`kind` は残すが、API は `asset` 以外を 400 で拒否)。設計書「まずは asset のみ」。
8. **画面の一覧の上限**: かんばん・タスク一覧は最大 10 ページ(2,000 件)まで読む。超えたら画面に件数を出す。プロジェクト一覧は 200 件まで。
9. **API の並べ替えは許可リスト**。それ以外の `ordering` は 400。同順位は id で固定(ページ送りがぶれない)。
10. **取り込み API の鍵が未設定なら、常に 401**(fail closed)。
