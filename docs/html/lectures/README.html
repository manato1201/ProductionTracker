講義資料 ― 基礎から、保守・拡張できるところまで

この資料は、ProductionTracker を題材にした講義です。プログラミングの基礎(Web の仕組み・Python・データベース)から始めて、 フレームワーク(Django・React)、アルゴリズム(状態機械・文字列・並行制御・暗号)、テスト、運用まで、1 つの実物のアプリで順に学びます。 最後には、自分で機能を 1 つ足せるようになることがゴールです。

合計で約 30 時間。1 回 = 1〜2 時間で区切れるようにしてある。

各回の形

どの回も、同じ順で進みます。

  1. この回の目標 と、前提(前の回のどこを使うか)
  2. 考え方 — まず言葉と図で。「なぜそうするのか」から
  3. コードを読む — このアプリの実際のコードの抜粋
  4. 手を動かす — 実行できる小さなコード(結果つき)
  5. よくある間違い
  6. 確認問題 と、答え

この資料の約束

  • 掲載したコードは、実行して確かめてある。 <!-- test --> の印が付いたコードは、テスト(backend/tracker/tests/test_docs.py)が毎回実行し、 「実行結果」と一致することを確かめる。<!-- excerpt: パス --> の印が付いた抜粋は、そのファイルに本当にある行かを確かめる。 つまり、この資料のコードは、書いてあるとおりに動く。ソースを直して文書が古くなると、テストが落ちる。
  • 図は、Markdown だけで読める mermaid 記法と、docs/diagrams/ の SVG の両方で載せている。HTML 版(docs/html/index.html)もある。
  • 本文の「このアプリでは」は、ProductionTracker の実際の設計を指す。一般論と区別して読むこと。
  • 分からない言葉は 用語集 へ。

読み方のおすすめ

あなたは おすすめの順
プログラミングが初めて L00 → L01 → L02 → L03 → L04 → … を順に。手を動かすを必ず実行する
Python は書けるが Web は初めて L01 → L03 → L04 → L05 → L06〜L09
Django / React は使ったことがある L06〜L09(アルゴリズム)→ L14(テスト)→ L16(運用)→ L17
保守・機能追加だけ急ぎたい 実践ガイド(レシピ)を先に。分からない所で、対応する講義へ戻る
