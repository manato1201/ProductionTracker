用語集

講義と実践ガイドに出てくる用語を、分野ごとに並べました。右端は、詳しく説明している回です。 このアプリに固有の用語(「アセット」「工程」「版」など)は、最初にまとめてあります。

このアプリの言葉

用語 意味 詳しくは
プロジェクト(Project) 作品や案件の単位。メンバーと役割を持つ L00
アセット / Entity 作る対象(例: 木箱・主人公)。path(例 assets/props/crate)を持つ er.md
工程 / Step 作業の種類(例: モデリング・FX) er.md
タスク(Task) 「あるアセットの、ある工程」の作業。状態を持つ L06
版(Version) 提出された成果物の版(v1, v2…)。レビューの対象 er.md
ノート(Note) タスクや版へのコメント er.md
状態(Status) タスクの進み具合: 未着手 / 進行中 / レビュー / 完了 L06
役割(Role) プロジェクト内の立場: アーティスト / レビュアー / 閲覧者 L05
取り込み(Ingest) 外部ツールの結果を API で受け取ること L08・L15
品質レポート AssetDataInsightSuite が出す、アセットごとの欠陥件数 integration.md
視覚検査の結果 VisualRegressionQATool の合否と差分率 integration.md
モチーフ 空の列に飾る ASCII の植物(種→芽→花→実) L12

Web・通信

用語 意味 詳しくは
HTTP Web の通信の約束事。リクエストとレスポンスの組 L01
URL 資源の場所を示す文字列(スキーム・ホスト・パス・クエリ) L01
メソッド GET(読む)・POST(作る)・PATCH(一部直す)・PUT(置き換え)・DELETE(消す) L01
ステータスコード 結果を示す数字。2xx 成功 / 4xx クライアントの誤り / 5xx サーバーの誤り L01
ヘッダ リクエスト/レスポンスの付加情報(Content-Type・Authorization など) L01
JSON データを書く文字列の形式。ほぼすべての API で使われる L01・L10
REST 資源を URL で表し、メソッドで操作する API の流儀 L01
API プログラムから使う窓口 L01
エンドポイント API の個々の URL L05
ページネーション 一覧を一定の件数ずつ返すこと L05
Cookie ブラウザが覚え、リクエストに自動で付ける小さな情報 L01
セッション ログイン状態をサーバー側で覚える仕組み L01・L09
CORS 別のオリジンからのリクエストをブラウザが許すかの約束 L01
オリジン スキーム + ホスト + ポートの組 L01
プロキシ 通信を中継するもの。リバースプロキシはサーバーの前に立つ L16
TLS / HTTPS 通信を暗号化し、相手を確かめる仕組み L09
DNS 名前(ドメイン)から IP アドレスを引く仕組み L01
キャッシュ 同じ応答を使い回すこと。Cache-Control で制御 L16

Python

用語 意味 詳しくは
型(type) 値の種類(整数・文字列・リスト…) L02
関数 名前を付けた処理のまとまり L02
クラス / インスタンス 設計図 / それから作った実体 L02

内包表記 リストなどを 1 行で作る書き方 L02

データベース

用語 意味 詳しくは
RDB 表(テーブル)でデータを持つ DB L03
テーブル / 行 / 列 表 / 1 件のデータ / 項目 L03
主キー 行を一意に決める値(通常は id) L03
外部キー 他の表の行を指す列 L03
正規化 重複を避けて表を分けること L03
SQL DB を操作する言語(SELECT / INSERT / UPDATE / DELETE) L03
JOIN 複数の表をキーでつなぐ L03
索引(インデックス) 検索を速くする仕組み。書き込みは少し遅くなる L03
一意制約(UNIQUE) 同じ値を 2 つ入れさせない L03・L08
CHECK 制約 値が条件を満たすことを DB が保証する L03
トランザクション 「全部成功するか、全部なかったことになる」まとまり L03・L08
ACID トランザクションの 4 性質(原子性・一貫性・分離性・永続性) L03
ロック 同時に触らせないための排他(select_for_update) L08
N+1 問題 一覧 1 回 + 各行ごとに追加の問い合わせが走る性能問題 L04
実行計画 DB が検索をどう行うかの手順(EXPLAIN) L03
SQL インジェクション 入力が SQL として解釈されてしまう脆弱性 L03・L15
マイグレーション DB の構造変更を記録・適用する仕組み L04
ダンプ / リストア DB の書き出し / 書き戻し L15

settings 設定を集めたモジュール L04・L16
シリアライザ オブジェクト ⇔ JSON の変換と入力検査 L05

認証(authentication) 「誰か」を確かめる L05・L09
認可 / 権限(permission) 「その人に許されているか」を確かめる L05

アルゴリズム・設計

用語 意味 詳しくは
状態機械(FSM) 状態と、許される遷移の表で振る舞いを定める L06
遷移表 「どの状態からどこへ行けるか」の一覧 L06
到達可能性 ある状態から別の状態へたどり着けるか(幅優先探索) L06
不変条件 常に成り立つべき性質 L06
正規化(パス) 表記の揺れをそろえる L07
最長一致 前方一致のうち最も長いものを選ぶ L07
トライ木 文字列を 1 文字ずつ枝分かれで持つ木 L07
計算量(O 記法) 入力が増えたとき、時間や領域がどう増えるか L07
Unicode / NFC / NFD 文字の規格 / 結合済みの形 / 分解した形 L07・L17
競合状態(race condition) 同時実行で結果が実行順に左右されること L08
冪等(べきとう) 同じ操作を何回行っても、結果が 1 回と同じ L08
Idempotency-Key 同じ要求の再送を見分けるための、クライアントが付ける印 L08
楽観的更新 成功を見込んで先に画面を更新し、失敗したら戻す L13
楽観的ロック / 悲観的ロック 衝突を後で検出 / 先に排他する L08
性質ベーステスト 「どんな入力でも成り立つ性質」を検査する L14
差分テスト 元の実装と新しい実装の結果を突き合わせる L17
ファズ でたらめな入力を大量にぶつけて、落ちないか確かめる L14
回帰テスト 直したバグが再発しないようにするテスト L14

認証・暗号・セキュリティ

用語 意味 詳しくは
ハッシュ データから固定長の「指紋」を作る一方向の関数 L09
ソルト パスワードのハッシュに混ぜる、ユーザーごとのランダム値 L09
PBKDF2 何度も繰り返してハッシュを遅くする、パスワード向けの方式 L09
定数時間比較 一致までの時間で情報が漏れない比較(hmac.compare_digest) L09
HMAC 鍵つきのハッシュ。改ざんの検出に使う L09
JWT 署名つきの情報(ヘッダ.本体.署名)。Cloudflare Access が使う L09
RS256 公開鍵方式の署名(秘密鍵で署名、公開鍵で検証) L09
JWKS 検証用の公開鍵の一覧 L09
CSRF ログイン中の利用者に、意図しない操作をさせる攻撃 L09
XSS 悪意あるスクリプトを画面に差し込む攻撃 security.md
SameSite Cookie を別サイトからの送信に付けるかの設定 L01
レート制限 一定時間のリクエスト数に上限を設ける L09
最小権限 必要な権限だけを与える L15・L16
fail closed 迷ったら閉じる(危険な設定なら起動しない・拒否する) L16
OWASP API Top 10 API の代表的な脆弱性の一覧 L16・security.md
秘密情報 パスワード・API キー・鍵・トークン。Git やログに出さない L15・L16
